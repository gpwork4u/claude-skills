# Composition Grammar：讓頁面不死板的組合法

頁面死板，通常不是因為顏色選錯，而是每個軸都用了預設值：置中、等寬卡片、同一種圓角、每個區塊一樣大聲。這份文件把頁面拆成五個彼此獨立的軸，選法、相容性與評分都寫在這裡。

互動版本：`examples/composition-lab.html`。裡面的 `GRAMMARS`、`MOTIFS`、`COMPAT`、`BUDGETS` 是本文件的資料來源，改規則時兩邊要同步。

---

## 五個正交軸

| 軸 | 管什麼 | 選項 | 換這一軸會得到 |
|---|---|---|---|
| **版面語法**（layout grammar） | 骨架：區塊怎麼排、項目怎麼列 | 10 種，見下表 | 一個結構上真正不同的方向 |
| **材料**（motif） | 質地：筆觸、色票、字體、角度集、選取隱喻、轉場動詞 | 見 `motif-library.md` | 同一個骨架換一種世界觀 |
| **表現力預算**（expression budget） | 音量分佈：哪個區域可以放開 | 每個區域 L0–L3 | 同一組合從後台到活動頁 |
| **密度**（density） | 間距倍率 | 疏 1.35／中 1／密 0.62 | 閱讀型 vs 工具型 |
| **種子**（seed） | 規則內的變化 | 任意整數，從 slug／卡號／地址雜湊 | 同一家人的不同臉 |

三個主軸各自獨立：10 種語法 × 9 種材料 × 5 組預算預設，就有 450 個起點，再乘上密度與種子。產生候選方向時（`style-genome.md` 的步驟 1–3），**每個候選至少要在版面語法或材料其中一軸不同**，不能只差預算或顏色。

---

## 先看內容的形狀

選版面語法之前，先判斷內容是哪一種形狀。形狀對了，語法幾乎就選好了。

| 形狀 | 特徵 | 例子 |
|---|---|---|
| 序列（seq） | 順序就是資訊 | 流程、時間軸、版本紀錄、課程 |
| 目錄（cat） | 很多同類項目要比較、篩選 | 商品、卡牌、路段行情、服務列表 |
| 敘事（nar） | 要被讀的論點或故事 | 品牌官網、文章、案例 |
| 網絡（net） | 項目之間有位置或關係 | 地圖、關係圖、有中心的生態系 |

一份內容可以同時有兩種形狀，例如租屋查證是「目錄＋網絡」，各給 0–2 分。

## 10 種版面語法

| 語法 | 擅長的形狀 | 骨架 | 手機上的變形 |
|---|---|---|---|
| 樣板 Template | （對照組） | 置中 hero、三張等寬卡、藥丸按鈕、logo 牆 | 堆疊。只當反例用 |
| 非對稱網格 Asymmetric 12-col | 通用 | 12 欄、左重右輕、懸掛編號、數字對齊基線 | 6 欄，編號仍懸掛在第 1 欄 |
| 編輯刊物 Editorial | 敘事 | 刊頭（期號／日期）、首字放大、雙欄＋欄線、目錄點線 | 單欄，保留刊頭與首字 |
| 帳簿索引 Ledger | 目錄 | 每個區塊都是一張表：欄位格、合計雙線、備註列、簽核列 | 收掉說明欄，欄位格改成單欄 |
| 標本陳列 Specimen board | 目錄 | 中心是物件，引線標出每個部位；下方是吊牌格，主打項跨兩格 | 引線改成編號圓點＋編號圖例 |
| 對角舞台 Diagonal stage | 敘事 | 斜切色帶分割畫面；項目沿對角線階梯排列；佐證區 skewY 反斜內容 | 斜角變小、階梯縮成 3% |
| 軌道 Orbit | 網絡 | 核心在中央，項目繞圓排列，角度就是索引 | 節點只留編號，清單在下方 |
| 橫向長卷 Hand scroll | 序列 | 往右展開的時間軸，scroll-snap，軸線上有節點 | 轉成直向時間軸，軸線移到左側 |
| 空間畫布 Spatial canvas | 網絡 | 項目有座標（A1–F4），用路線連接，下方是座標圖例 | 畫布改 4:3，節點只留編號 |
| 卷宗疊紙 Dossier stack | 敘事 | 有頁籤的一疊紙，點頁籤把那張抽到最上面；其他區塊也是疊紙 | 頁籤橫向捲動，偏移變小 |

實作提醒：

- 用 container query（`@container site (max-width:…)`），讓語法跟著**容器**寬度變形，不是跟著 viewport
- 響應式是變形，不是塌陷。每種語法在窄螢幕都要有自己的版本，不准全部變成置中堆疊
- 卡片只在「卡片本身有意義」的語法裡出現：標本吊牌、卷宗的紙。其他語法用 rows、表格、軸線

## 版面 × 材料相容性

分數規則跟 `style-genome.md` 的 pairwise compatibility 相同（+2 強化／+1 相容／0 中性／-1 要有理由／-2 除非是招牌否則不成立）。完整矩陣與理由在 `composition-lab.html` 的 `COMPAT`。常用的強化組合：

| 材料 | +2 | -1 以下 |
|---|---|---|
| 白底製圖 | 非對稱網格、標本陳列、空間畫布 | 對角舞台、樣板 |
| 孔版印刷 | 編輯刊物 | 帳簿索引 |
| 木刻朱印 | 編輯刊物、橫向長卷（手卷） | 對角舞台、樣板 |
| 航海圖 | 空間畫布、軌道（羅經花） | 樣板 |
| CRT 終端機 | 帳簿索引 | 編輯刊物、對角舞台、軌道、樣板 |
| 預告信 | 對角舞台、卷宗疊紙 | 帳簿索引（-2）、非對稱網格、樣板 |
| 門牌 | 空間畫布、帳簿索引 | 對角舞台、樣板 |
| 評級卡盒 | 標本陳列、卷宗疊紙 | 編輯刊物、樣板 |

**樣板和所有材料都是 -1 或以下**（中性材料除外）。換材料救不了樣板，因為問題在骨架。

### 受控矛盾

相容性為負的組合可以當招牌，但要同時符合：

1. 只出現在**一個區域**，其他區域回到 L0–L1
2. 寫下理由（例如「CRT × 軌道：只用在雷達掃描的狀態頁」）
3. 不碰可讀核心

## 表現力預算

把頁面切成區域，每個區域給一個等級。等級定義見 `expressive-ui.md`；這裡只管分配。

| 區域 | 說明 |
|---|---|
| nav | 導覽列 |
| hero | 主視覺／頁首 |
| body | 主要內容（項目列表） |
| proof | 佐證（數字、引言） |
| list | 次要列表（文章、紀錄） |
| cta | 行動區 |
| foot | 頁尾 |

預設組：

| 預算 | 適用 | nav | hero | body | proof | list | cta | foot |
|---|---|---|---|---|---|---|---|---|
| 安靜 | 後台、SaaS | 0 | 0 | 0 | 0 | 0 | 0 | 0 |
| 刊物 | 部落格、文件 | 1 | 1 | 1 | 1 | 1 | 0 | 0 |
| 品牌 | 官網、商品頁 | 2 | 3 | 1 | 1 | 1 | 2 | 1 |
| 活動 | 活動頁、作品集 | 2 | 3 | 2 | 3 | 2 | 2 | 1 |
| 全開 | 反例 | 3 | 3 | 3 | 3 | 3 | 3 | 3 |

規則：

- **安靜區至少 3 個**（L0 或 L1）
- **L3 最多 2 個**
- 查證、金流、表單、資料表所在的區域固定 L0–L1
- 同一個網站的不同頁面可以用不同預算，但材料不變。例如文件頁用「刊物」、首頁用「品牌」、完成畫面才用 L4

實作：區域元素加 `data-x="0..3"`，材料的 CSS 只透過等級選擇器介入（寫法見 `expressive-recipes.md`）。

## 種子變異

在材料的規則內，用種子挑值。輸入要是穩定的識別碼，同一篇文章每次都長一樣：

```js
const hash = s => { let h = 2166136261; for (const ch of s) { h ^= ch.codePointAt(0); h = Math.imul(h, 16777619); } return h >>> 0; };
const mulberry = a => () => { a |= 0; a = a + 0x6D2B79F5 | 0; let t = Math.imul(a ^ a >>> 15, 1 | a); t = t + Math.imul(t ^ t >>> 7, 61 | t) ^ t; return ((t ^ t >>> 14) >>> 0) / 4294967296; };
const rng = mulberry(hash(post.slug));
const angle = motif.angles[Math.floor(rng() * motif.angles.length)];
```

可以交給種子的值：

- 角度集裡的角度（只給 display 標題與底板，內文永遠 0°）
- 哪一項是主打（featured）
- 空間畫布的座標、軌道的起始角
- 裝飾件編號：圖號、期號、海圖編號、評級證號
- 主視覺圖的比例與位置

不要交給種子的：色票、字體、版面語法、預算。這些是契約，不隨機。

## 評分

組合實驗室用的公式，可以直接拿來給候選方向打分：

```text
total = 58
      + 相容性 × 9          （-2 到 +2）
      + 內容適配 × 7        （0 到 2；通用語法算 1）
      + 預算分               （安靜區 ≥ 3 → +4，否則 -6；L3 超過 2 個，每多一個 -3）
      - cliché 數 × 5
```

- 80 以上：可以直接當候選方向
- 62–79：可用，有一層要再調
- cliché ≥ 5：重抽骨架（換版面語法或字體聲音，不是換強調色）

這個分數補充 `style-genome.md` 的 100 分制，不取代它；前者看組合是否成立，後者看是否符合產品。

## 隨機組合的抽法

要產生候選方向時可以這樣抽，結果比從零發想更容易跳出預設：

1. 排除樣板與中性材料
2. 排除相容性為負的組合（除非刻意找受控矛盾）
3. 排除內容適配為 0 的語法
4. 依 `2.2^(相容性 + 內容適配)` 加權抽一組
5. 預算從品牌／活動／刊物裡挑
6. 抽到的組合仍要跑 cliché 偵測與無障礙檢查

## 輸出

組合定案後，在 StyleGenome 契約裡加上這幾段（範例由組合實驗室的「複製 YAML」產生）：

```yaml
design:
  layout:
    grammar: asymmetric-12-column
    content_shape: nar
    density: medium
    responsive: transform-not-collapse
  motif:
    key: draft
    world_material: "工程圖、尺寸線、圖框標題欄"
    angle_set: [0, 0, 90]
    transition_verb: draw
    legibility_core: "內文、表單、數字"
  expression_budget:
    nav: L2
    hero: L3
    body: L1
    proof: L1
    list: L1
    cta: L2
    foot: L1
  seed_source: post.slug
```
