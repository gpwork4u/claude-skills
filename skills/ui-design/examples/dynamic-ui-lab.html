動態 UI 實驗室

遊戲 UI 不死板，是因為每個元件都有「從哪裡來、怎麼走、走多快、怎麼停」的答案。下面把這些答案拆成七個軸，再用 18 個可以直接操作的模式示範：第一批是單一元件的動態，第二批是整個系統（佇列、進度、導覽、對話）的動態。所有模式共用同一組彈簧參數，切換「能量」可以看同一個模式變成不同性格。

能量

動態語法：讓 UI 不死板的七個軸

  • 起點Origin東西從哪裡長出來：從按下的按鈕、從螢幕邊緣、從游標所在的位置。沒有起點的東西只能憑空淡入。
  • 路徑Path移動的軌跡：直線、弧線、繞圈、拋物線。弧線讓排列有方向感，扇形和手牌都靠它。
  • 節奏Rhythm一群元素依什麼順序出場：由近到遠、由中心向外、依序、亂序。收合時通常反過來。
  • 物理Physics用彈簧的剛度與阻尼取代固定時長，讓動作可以被打斷、可以回彈，也帶有慣性。
  • 輸入映射Input把游標角度、距離、按住時間、拖曳速度直接變成 UI 參數，而不只是「點了就觸發」。
  • 連續性Continuity元素在狀態之間保持身分：按鈕變成面板、方塊推進成整頁，使用者看得出「它去哪了」。
  • 回饋Feedback打擊感：瞬間停頓、震動、粒子、浮字、數字跳動。成功和失敗要有不同的手感。

第二批：系統型動態

元件型動態回答「這顆按鈕怎麼動」；系統型動態回答「一群東西的關係怎麼變」：誰排前面、哪些解鎖了、我走到哪裡、累積了多少、剛剛選了什麼。這類動態的重點是讓使用者在變化發生前看得到後果，發生時追得到每個東西去了哪裡。

減少動態開啟時（或系統設定偏好減少動態），彈簧改成瞬間到位，震動、粒子、傾斜全部停用，但每個模式的功能都還能用。所有模式都能只靠鍵盤操作。
